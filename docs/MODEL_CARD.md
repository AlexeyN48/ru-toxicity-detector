## 1. Детали модели

| Поле | Значение |
|---|---|
| Название | ru-toxicity-detector |
| Версия модели | 0.1.0 (ещё не обучена) |
| Тип | Transformer-энкодер (BERT) + линейный классификатор поверх `[CLS]` |
| Базовая модель | [`ai-forever/ruBert-base`](https://huggingface.co/ai-forever/ruBert-base): 178M параметров, BPE-токенизатор, словарь 120 138 токенов, предобучена на 30 ГБ русских текстов ([Zmitrovich et al., 2023](https://arxiv.org/abs/2309.10931)) |
| Baseline для сравнения | [`cointegrated/rubert-tiny2`](https://huggingface.co/cointegrated/rubert-tiny2) — маленькая модель для оценки выигрыша от размера |
| Задача | бинарная классификация текста: `токсичный` (1) / `нетоксичный` (0) |
| Вход | текст одного комментария на русском, до 128 токенов |
| Выход | вероятность класса «токсичный» от 0 до 1 и метка по порогу |
| Фреймворк | PyTorch, Hugging Face `transformers` |
| Лицензия базовой модели | Apache-2.0 |
| Авторы | команда проекта (см. README) |

**Планируемая процедура обучения**

| Параметр | Значение |
|---|---|
| Эпохи | 3, ранняя остановка, если ROC-AUC на validation не растёт 2 эпохи подряд |
| Learning rate | 2e-5, линейное затухание, warmup 10 % шагов |
| Batch size | 32 |
| Максимальная длина | 128 токенов, динамический паддинг |
| Weight decay | 0.01 |
| Точность | fp16 (mixed precision) |
| Seed | 42 |
| Железо | NVIDIA RTX 4060, 8 ГБ |
| Ожидаемое время | ~5–7 минут на полное обучение |

Подбор гиперпараметров: learning rate из {1e-5, 2e-5, 3e-5}, по 2 seed на каждый,
лучшая конфигурация выбирается по ROC-AUC на validation.

## 3. Метрики

**Главная метрика — ROC-AUC.** Она не зависит от выбранного порога и показывает, насколько
хорошо модель ранжирует токсичные комментарии выше нетоксичных. По ROC-AUC проходит
«аукцион» champion vs challenger в retraining-цикле (ДЗ 2).

**Дополнительные метрики:**

- F1 по классу «токсичный» и F1 macro;
- Precision и Recall по классу «токсичный»;
- PR-AUC — устойчивее ROC-AUC при дисбалансе классов (токсичных ~1/3);
- время инференса одного комментария.

**Порог классификации** подбираем на validation: максимальный F1 при условии
Recall ≥ 0.85. Для очереди модерации пропустить токсичный комментарий хуже, чем отправить
лишний на проверку человеку.

**Целевые значения** (тестовая выборка):

| Метрика | Цель | rubert-tiny2 | ruBert-base |
|---|---|---|---|
| ROC-AUC | ≥ 0.95 | — | — |
| PR-AUC | ≥ 0.90 | — | — |
| F1 (токсичный) | ≥ 0.85 | — | — |
| Recall (токсичный) | ≥ 0.85 | — | — |
| Precision (токсичный) | ≥ 0.80 | — | — |
| Инференс, мс/комментарий (GPU) | ≤ 20 | — | — |

Прочерки заполним после обучения. Метрики считаем на test один раз, после того как выбраны
гиперпараметры и порог.

## 6. Версия данных

### Датасет

| Поле | Значение |
|---|---|
| Название | Russian Language Toxic Comments |
| Источник | [Kaggle: blackmoon/russian-language-toxic-comments](https://www.kaggle.com/datasets/blackmoon/russian-language-toxic-comments) |
| Откуда тексты | комментарии с 2ch.hk и pikabu.ru |
| Дата публикации | 2019 |
| Размер | 14 412 уникальных комментариев |
| Баланс классов | токсичные — 4 826 (33,5 %), нетоксичные — 9 586 (66,5 %) |
| Длина комментария | в среднем 175 символов, минимум 21, максимум 7 403 |
| Лицензия | **нужно проверить** на странице датасета до начала обучения |
| sha256 исходного файла | будет записан в `data/manifest.json` при первой загрузке |

Описание датасета и статистика: [Dolgushin, Bidulya, 2022](https://pureportal.spbu.ru/files/97970960/Dolgushin_Bidulya2022_Chapter_ToxicMessagesClassificationInS.pdf).

### Разбиение

Стратифицированное разбиение по классу с фиксированным seed = 42:

| Часть | Доля | Примерный размер | Для чего |
|---|---|---|---|
| train | 70 % | ~10 088 | дообучение |
| validation | 15 % | ~2 162 | выбор порога, ранняя остановка, подбор гиперпараметров |
| test | 15 % | ~2 162 | итоговые метрики и fairness-анализ; используется один раз |

### Предобработка

- удаление полных дубликатов и пустых строк;
- обрезка пробелов по краям;
- регистр, пунктуацию, мат и эмодзи **не трогаем**: они несут сигнал о токсичности;
- тексты длиннее 128 токенов обрезаются токенизатором (см. «Ограничения»).

### Версионирование

- Сырые данные в git не хранятся. В репозитории лежат `data/README.md` (как скачать) и
  `data/manifest.json` (версия датасета, sha256 файлов, размеры сплитов, seed).
- Каждая новая порция разметки от модераторов (retraining-цикл, ДЗ 2) создаёт новую
  версию датасета `vN+1`. Номер версии данных записывается в метаданные модели.

| Версия данных | Состав | Используется в модели |
|---|---|---|
| v1 | исходный Kaggle-датасет | 0.1.0 (план) |
